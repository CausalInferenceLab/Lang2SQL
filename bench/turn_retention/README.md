# 100턴 대화 정확도 평가

같은 100개 질문을 매번 빈 대화 기록에서 묻는 조건(`fresh`)과 한 세션에 순서대로 묻는 조건(`long`)을 비교한다. 한 쌍에서 모델·질문 순서·데이터·가용한 업무 정의·도구·호출 예산이 같다. 앞선 질문이나 답을 가리키는 후속 질문은 이 평가에 포함하지 않는다.

[600개 응답의 결과와 구간별 비교](RESULTS.md)

## 실행 및 채점

1. [fixture.py](fixture.py)가 고객·주문·주문상품 세 테이블을 만들고, 2025년 월·지역별 주문 수, 구매 고객 수, 상태별 집계, 수량·할인·환불·매출 질문을 고정한다. 실행 전 질문과 정답 SQL·기대값이 든 manifest, DB 두 개의 SHA-256을 기록한다. 일반 질의에 사용하는 DB와 검증 전용 DB의 스키마는 같고 데이터는 다르다.
2. 10번째 질문을 처리한 직후 양쪽에서 같은 `term_custom` 호출로 팀의 ‘인정매출’을 등록한다. 결제가 PAID인 주문상품의 수량×단가에서 행별 할인액과 환불액을 각각 한 번 뺀 합계다. 질문 30·60·90은 다른 월의 인정매출을 묻는다. 10턴 등록은 사람이 명시한 설정 작업으로, 100개 질의나 모델 호출 수에 포함하지 않는다.
3. 실제 `ContextConcierge`와 `agent_loop`를 사용한다. 매 턴 Discord 경로와 같은 순서로 도구 메시지를 압축하고 세션을 저장한다. fresh는 다음 질문 직전에 대화 기록만 비운다. 각 조건·반복은 독립된 메타데이터 저장소를 사용하며, 팀 정의는 유지한다. 모델에는 `explore_schema`, `run_sql`, `ask_user`를 제공한다. 질문·도구 결과·시스템 프롬프트에 정답 SQL과 검증용 데이터를 제공하지 않는다.
4. **답변 정확도**는 최종 응답에서 읽은 숫자와 제출 SQL의 실제 결과가 모두 기대값과 일치할 때 정답으로 센다. SQL 블록이 생략되면 Discord가 함께 표시하는 현재 턴의 마지막 성공 쿼리를 사용한다. 마지막 SQL 도구 호출이 실패했다면 이전 성공 쿼리를 채택하지 않는다. 자연어에서 숫자를 하나로 결정할 수 없으면 답변 채점은 실패한다. SQL 결과 정확도와 실행 가능 여부도 별도로 기록한다. 되묻기는 `ask_user`, 명시적 `CLARIFY:` 또는 SQL 없이 끝난 물음표 응답을 기준으로 센다.
5. **정의 적용률**은 30·60·90턴의 SQL을 기본 DB와 검증용 DB 양쪽에서 실행해 두 결과가 각각 그 DB의 업무 정의 기대값과 일치한 비율이다. 한 DB에 맞춘 상수 답변은 여기서 걸러진다. 기존 팀 정의가 시스템 프롬프트에 재주입되는 구성이다. 이 수치는 그 상태에서의 정의 사용을 측정하며, 저장된 정의를 제공하지 않았을 때의 회상 능력은 별도 실험이 필요하다.
6. 각 조건을 세 번 반복한다. 반복별 seed는 26701·26702·26703이며, 동일 반복의 두 조건에 같은 seed를 사용한다. `gpt-4.1-mini-2025-04-14`, temperature 0.2, 호출당 출력 1,024토큰, 문항당 모델 호출 최대 16회다. 총 600개 응답을 분모에 포함한다. 입력·캐시 입력·출력은 API 사용량이며, 표준 요금 추정은 각각 미캐시 입력 $0.40, 캐시 입력 $0.10, 출력 $1.60/백만 토큰을 적용한다. [모델 요금표](https://developers.openai.com/api/docs/models/gpt-4.1-mini)

## 재현

```sh
uv sync
uv run python -m bench.turn_retention.run freeze /tmp/turn267-fixture
# OPENAI_API_KEY를 설정하고 아직 존재하지 않는 출력 디렉터리를 지정한다.
uv run python -m bench.turn_retention.run run /tmp/turn267-fixture --output /tmp/turn267-run
uv run python -m bench.turn_retention.summarize /tmp/turn267-run
```

채점 집계는 API 키가 필요 없다. 공개 실행 기록은 아래 명령으로 다시 집계한다.

```sh
python -m bench.turn_retention.summarize bench/turn_retention/results
```

기록된 실험은 `master`의 `b443df4` 위에 스키마 확인 안내 및 최종 SQL 실행 오류 수정 1회를 적용한 로컬 런타임에서 수행했다. 이 런타임 소스의 SHA-256과 git 커밋은 [config.json](results/config.json)에 있다. 평가 코드는 설치된 Lang2SQL을 사용한다. 기본 브랜치에서 실행하면 그 브랜치의 동작을 측정하므로 두 런타임을 직접 혼합 비교하지 않는다. SQLite 파일의 물리 해시는 SQLite 빌드에 따라 달라질 수 있다. 질문·정답 manifest 해시도 함께 비교한다.

## 해석 범위

하나의 합성 DB, 질문 순서 하나, 모델 스냅샷 하나로 측정한다. 같은 질문을 세 번 반복한 점을 고려해 반복별 결과와 새 세션 기준선을 함께 비교한다. 길이가 늘수록 난이도도 달라질 수 있어 첫 20턴과 마지막 20턴의 점수 차이만으로 장기 대화 효과를 추정할 수 없다. 정의 적용과 문답 정확도, 추가로 지불한 토큰은 각각 별도 지표다.
