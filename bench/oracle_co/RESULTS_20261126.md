## Failures retained and changes made

- Codex config overrides initially included disabled server stubs with no transport, then a JSON object where TOML fields were required. The session launcher now passes individual fields and only supplies unrelated disabled servers for interactive mode, where their full configuration exists.
- Protected Documents-folder access stalled newly started MCP processes. Private runtime env files were moved to the workspace with mode 0600, and the dedicated demo credentials rotated. Subsequent registered MCP, follow-up and fresh-memory checks passed.
- The missing-definition response previously instructed the model to bypass candidate review through term_custom. It now points to context_candidates and operator approval; a regression assertion checks that instruction while the existing test verifies SQL was not executed.
- Native macOS screen capture returned “could not create image from display.” Terminal-output recording is labeled as terminal re-rendering rather than native screen capture. Recording-harness failures must not be presented as product passes.
- Current operator approval and binding remain separate writes. Do not automatically retry an interrupted approval; inspect candidate/definition state. No transactional recovery or in-Codex human approval was added in this patch.

The real model checks use the existing `bench/oracle_view/long_context.py` driver; the external model produces the SQL/tool calls. These CO checks do not replace the earlier synthetic 100-turn test and are not evidence of general accuracy improvement. The live scope is prepared separately from rehearsal so sales 매출 remains undefined for the presentation.

Interactive recording found that `/new` opens a worktree picker in the installed Codex version. Subsequent question input went into that picker instead of a conversation. The runbook now uses exit/reopen; this is a client interaction failure, not evidence of memory loss. The failed take is retained.

An interactive finance restart also displayed the Codex update picker. The operator stopped the take. The launcher now sets check_for_update_on_startup=false per invocation; the installed binary exposes that setting. No Codex upgrade was performed.
