## 장기 대화 검증의 해석

9·10·11월 순매출 세 패턴을 반복하며 “같은 기준으로 그다음 달은?”이라는 후속 질문을 섞었다. 실제 Codex `resume`을 사용했고, 독립 검증기가 동일 세션 ID, 시작·종료일, 승인 뷰, SQL 반환값을 확인한다. 비교 지점에서는 질문을 완전한 문장으로 풀어 새 세션에서도 실행한다.

100개의 서로 다른 문제, 다중 모델 통계 비교, 일반적인 정확도 향상, 모델 가중치 학습을 입증한 것은 아니다. 모델이 승인된 정의를 매번 다시 조회하는 경로의 지속성을 검증한다. #267/#268의 더 넓은 연구 범위는 이 결과만으로 닫지 않는다.

Codex resume의 `turn.completed.usage`는 누적 카운터다. 최종 누적값을 세션 사용량으로 쓰며, 턴별 카운터를 합산하지 않는다. 별도 새 세션 비교의 사용량은 따로 합산한다. 금액 비용으로 환산하지 않았다.

## 실패 사례와 수정

- 초기 마케팅 정의는 “활동한 고객”으로 모호했고 컬럼도 `NET_AMOUNT`였다. Codex는 인원수 집계를 거부하고 재질문했다. 최종 로그인일, 고객당 한 행, `CUSTOMER_COUNT`의 뜻을 명시한 뒤 조회가 통과했다.
- MCP 연결만으로는 단순한 업무 정의 발언을 자동 저장하지 않는 사례가 있었다. 발표용 Codex 작업 폴더의 AGENTS.md에 후보 추출 지침을 추가한 뒤 저장 요청 없이 후보 생성되는 것을 확인했다.
- EXECUTE 권한만 있는 계정에서 패키지 본문이 보이지 않아 변경을 탐지할 수 없는 사례가 있었다. 본문 가시성을 필수로 검사하도록 수정했다. 패키지 검증은 별도 소유자 계정으로 수행했고 이 계정을 읽기 전용이라고 부르지 않는다.
- Oracle은 빈 문자열을 NULL로 취급하므로 빈 값 저장 회귀가 실패했다. EMPTY_CLOB와 행 존재 여부를 구분해 기존 KV 동작을 유지했다.

실패 원문과 최종 실행 로그는 로컬 검증 자료에 함께 보존했다. Git에는 합성 데이터 결과와 요약을 넣었으며 접속 비밀번호·환경 파일은 포함하지 않았다.
