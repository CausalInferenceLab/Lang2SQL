# BIRD Mini-Dev SQLite evidence 평가

2026년 11월 22일 · evidence가 있는 365문항 · SQLite DB 11개 · 모델 2개 × 조건 3개 · 총 2,190건

## 배경과 평가 조건

Lang2SQL은 `term_custom`으로 등록한 지식을 시스템 메시지에 자동으로 넣는다.
같은 문항별 힌트가 있을 때 이 전달 방식과 질문에 직접 붙이는 방식이 정답 SQL을
만드는 데 어떤 차이를 보이는지 비교했다. 힌트 없이 질문만 주는 조건도 함께
실행해 두 전달 방식의 기준점을 마련했다.

| 조건 | 사용자 메시지 | 첫 모델 호출 전 KV와 시스템 메시지 |
|---|---|---|
| A · KV 등록 | 질문 | 실제 `term_custom`으로 `team` 범위에 evidence 원문 1건 등록. 제품이 `Business Terminology` 섹션에 자동으로 추가 |
| B · 질문 첨부 | 질문과 같은 evidence 원문 | 빈 KV |
| D · 질문만 | 질문 | 빈 KV |

- **데이터**는 BIRD Mini-Dev 2026 SQLite `38818fc`의 500문항 가운데 공백을 제외한 evidence가 있는 365문항이다. 조건마다 같은 문항을 한 번씩 평가했다. [BIRD 데이터 리비전](https://huggingface.co/datasets/birdsql/bird_mini_dev/commit/38818fcbc46038129592680c51b2c8b597aac27c) · [실행 manifest](results/sqlite365-v1/manifest.json)
- **모델과 제품**은 `gpt-4.1-mini-2025-04-14`, `gpt-4.1-2025-04-14`, Lang2SQL 제품 소스 `e0a7fb1`로 고정했다. 매 문항에서 새 세션과 KV를 사용했다. 공통 시스템 메시지는 테이블 이름을 제공하며 컬럼 정보는 모델이 해당 테이블의 `explore_schema`를 호출할 때 반환된다. 모델은 `run_sql`과 `explore_schema`를 선택적으로 사용한다.
- **예산**은 문항당 모델 호출 8회, 호출당 출력 4,096토큰, API 120초, 문항 480초, SQL 30초, 최종 결과 100,000행이다. 조건·모델 조합당 동시성은 4이고 일부 조합을 병행했다. 각 조합의 첫 6문항은 기술 점검을 겸하며 같은 분모에 들어간다.
- **채점**은 최종 답변의 단일 SQL 블록과 정답 SQL을 동일한 읽기 전용 DB에서 실행한 뒤 행 튜플 집합을 비교한다. 행 순서와 중복은 무시하고 열 위치와 값은 유지한다. 실패한 문항도 분모 365에 포함한다. 정답 SQL 365개의 실행 가능 여부를 먼저 확인했다. [BIRD EX 비교 규칙](https://github.com/bird-bench/mini_dev/blob/1c49a375e76c471e218564da3f4617513d33e371/evaluation/evaluation_ex.py#L17) · [정답 SQL 사전 점검](results/sqlite365-v1/gold_check.json)

### 동일 문항의 정오답 전환

왼쪽만 정답과 오른쪽만 정답을 함께 표시한다. 주 비교는 A−B이며 B−D와 A−D는
보조 비교다. 문항 단위 양측 정확 McNemar 검정을 계산하고 여섯 조건 비교에
Holm 보정을 적용했다.

| 모델 | 비교 | EX 차이 | 왼쪽만 정답 | 오른쪽만 정답 | p | Holm 보정 p |
|---|---|---:|---:|---:|---:|---:|
| GPT‑4.1 mini | A−B | −4.93%p | 22 | 40 | 0.030 | 0.150 |
| GPT‑4.1 mini | B−D | +5.21%p | 42 | 23 | 0.025 | 0.149 |
| GPT‑4.1 mini | A−D | +0.27%p | 28 | 27 | 1.000 | 1.000 |
| GPT‑4.1 | A−B | +0.55%p | 9 | 7 | 0.804 | 1.000 |
| GPT‑4.1 | B−D | −0.55%p | 5 | 7 | 0.774 | 1.000 |
| GPT‑4.1 | A−D | 0.00%p | 7 | 7 | 1.000 | 1.000 |

mini에서 B는 A보다 18문항, D보다 19문항 더 맞혔다. 같은 DB의 문항을 함께
취급한 민감도 점검에서 mini의 A−B는 DB 단위 재표집 95% 구간이
**−9.26~0.00%p**였다. 11개 DB를 복원 추출해 문항 수로 가중한 percentile
bootstrap을 100,000회 수행했다. DB 단위 부호 순열 검정의 보정 전 p는
mini A−B에서 0.121, B−D에서 0.066이었다. 조건별 차이는 이 문항 집합의
단일 실행에서 관측한 값으로 해석한다.

컬럼 조회 문항은 테이블을 지정한 `explore_schema`가 한 번 이상 성공한 경우다.
도구 호출 수에는 실패한 호출도 포함한다. 문항 시간에는 API 대기와 도구 작업이
포함되며 별도 채점 시간은 제외한다. 총 7,026회 모델 호출 모두 사용량이
기록됐고 API 오류는 0건이었다.

- **A의 자동 주입**은 두 모델의 실제 첫 요청 730건에서 전수 확인했다. 모든 A의 시스템 메시지에서 해당 evidence 원문이 정확히 한 번 나타났다. B의 첫 사용자 메시지에서도 동일 원문을 모두 확인했다. 공통 시스템 프롬프트와 도구 정의의 해시는 문항별로 일치했다.
- **GPT‑4.1의 실행 오류** 896건을 같은 SQLite에서 다시 확인한 결과, 860건은 `no such column`, 16건은 문법 오류, 13건은 `no such table`, 6건은 모호한 컬럼 참조, 1건은 인식 불가 토큰이었다. 이 실행에서 GPT‑4.1은 두 도구를 한 번도 호출하지 않았다.
- **mini의 결과 불일치** 665건은 행·열 수가 같고 결과가 다른 경우 468건, 열 수는 같고 행 수가 다른 경우 125건, 빈 결과 57건, 열 수가 다른 경우 15건이었다. 분류는 채점 당시 행 수와 제출·정답 SQL의 결과 열 수를 기준으로 했다. 호출 예산을 소진한 156건 중 155건은 도구 오류가 있었고 112건은 중간 SQL 실행에 한 번 이상 성공했다.
- **B만 맞힌 mini 40문항** 모두 A에 evidence가 주입됐다. A의 실패는 결과 불일치 31건, 호출 소진 5건, 최종 SQL 누락 3건, 실행 오류 1건이었다. A−B에는 시스템 메시지와 사용자 메시지의 위치 차이와 용어 섹션의 렌더링 차이가 함께 포함된다.

| 문항 | 실제 사례 | 확인한 결과 |
|---|---|---|
| 87 · GPT‑4.1 B | `rulings.card_name` 참조. 기준 SQL은 `rulings`와 `cards`를 `uuid`로 연결 | `no such column: card_name` |
| 111 · mini B | `TEXT` 컬럼 `power`를 숫자로 변환하는 `CAST` 누락 | 예측 0, 정답 6,410 |
| 116 · mini A/B | A는 `multiverseId`, B는 기준 SQL과 같은 `uuid`로 조인 | A는 언어 2개, B와 정답은 11개 |

생성 SQL은 각 실행의 `predictions.jsonl`에서 `question_id`로 찾을 수 있다.
도구 호출·실패 유형·결과 모양은 같은 실행의 `records.json`과 `scores.json`에
기록했다. [실행별 결과 파일](results/sqlite365-v1/)
