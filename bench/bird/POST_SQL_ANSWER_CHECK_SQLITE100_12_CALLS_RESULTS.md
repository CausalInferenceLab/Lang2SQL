## 모델 호출 예산과 정확도

합산 신뢰구간은 동일 문항의 여섯 조합을 묶은 DB·난이도 층화 부트스트랩 50,000회로 구했습니다. 합산 p값은 문항 단위 양측 부호 반전 검정입니다.

| 호출 상한 | 미적용 EX | 적용 EX | 변경 효과 (%p) | 95% 신뢰구간 (%p) |
| ---: | ---: | ---: | ---: | ---: |
| 8회 | 151/600 (25.17%) | 153/600 (25.50%) | +0.33 | [-2.50, +3.17] |
| 12회 | 147/600 (24.50%) | 149/600 (24.83%) | +0.33 | [-2.50, +3.00] |

12회 비교의 p값은 0.911이며 DB 11개를 묶은 민감도 분석의 p값은 0.906입니다. 두 호출 상한에서 관측한 프롬프트 효과의 차이는 +0.00%p (문항 재표본추출 95% 구간 [-3.83, +3.83]%p)입니다. 8회 결과는 기존 실행이며, 두 실험의 실행 시점과 군 순서가 다릅니다. [8회 결과 PR #317](https://github.com/CausalInferenceLab/Lang2SQL/pull/317)

| 12회 실행 지표 | 미적용 | 적용 |
| --- | ---: | ---: |
| 모델 호출 9~12회 사용 | 49 | 52 |
| 9~12회 사용 후 최종 SQL 제출 | 19 | 27 |
| 9~12회 사용 후 최종 EX 정답 | 3 | 8 |
| 12회 한도 소진으로 미제출 | 30 | 25 |
| 실제 도구 실행 합계 | 1,525 | 1,636 |
| 1~8회 사용 후 최종 EX 정답 | 144 | 141 |

최종 정답 순증 2건은 9~12회 사용 구간의 5건 증가와 1~8회 사용 구간의 3건 감소를 합한 값입니다. 적용군의 9~12회 정답 8건 중 5건은 첫 조회의 오답을 후속 SQL로 회복해 최종 제출에 유지한 경우입니다.

8회 실험에서 한도를 소진했던 같은 문항을 12회 실험에서 다시 집계했습니다.

| 군 | 8회 한도 소진 | 12회 실험에서 정답 | 그중 9~12회 사용 |
| --- | ---: | ---: | ---: |
| 미적용 | 46 | 3 | 1 |
| 적용 | 37 | 6 | 2 |

Luna 미첨부 적용군의 문항 37은 8회 실험에서 8회에 EX 0, 12회 실험에서 3회에 EX 1이었습니다. 이전 실행에서 한도를 소진한 문항의 정답 전환에는 이런 실행 경로 변화도 포함됩니다.

8회와 12회 실행의 같은 군 첫 모델 요청 1,200쌍에서 시스템 메시지, 질문, 도구 스키마를 대조했습니다. [호출 예산 비교](results/post-sql-answer-check-314-sqlite100-12-v1/call-budget-comparison.json) · [문항별 예산과 결과](results/post-sql-answer-check-314-sqlite100-12-v1/call-budget-pairs.jsonl)

## 실험 설정

미적용군은 `fb1f36e9b0980c5e593d2fddb5ecc6607cd101d7`, 적용군은 `f4635ea567698f32d788688d327d2af33b59de9b`입니다. 두 군 모두 PR #316에서 파생한 12회 벤치 커밋 `bf8bffa17f19cb0752b98f2e93c053e1679c76f5`를 사용했습니다. [제품 PR #314](https://github.com/CausalInferenceLab/Lang2SQL/pull/314) · [벤치마크 PR #316](https://github.com/CausalInferenceLab/Lang2SQL/pull/316)

첫 모델 요청 600쌍에서 사용자 메시지와 도구 스키마·순서가 모두 일치했습니다. 적용군 시스템 메시지에서 PR #314가 추가한 검증 지시 문단을 제거하면 미적용군과 일치했습니다. 두 군 모두 `run_sql`, `explore_schema`, `enrich_schema`, `term_custom`, `org_setup`, `ask_user`, `remember`, `ingest_doc`, `confirm_ingest`까지 기본 도구 9개를 첫 요청에 포함했습니다. 각 문항은 새 세션과 빈 인메모리 저장소에서 시작했고, 문서 도구는 인라인 본문을 받도록 구성했습니다. [요청 검증](results/post-sql-answer-check-314-sqlite100-12-v1/first-request-audit.json) · [스모크 검증](results/post-sql-answer-check-314-sqlite100-12-v1/smoke-first-request-audit.json)

고정 표본은 BIRD Mini-Dev의 SQLite 11개 DB에서 뽑은 100문항입니다. DB 지문과 기준 SQL 100개의 실행을 확인했습니다. EX는 SQLite에서 실행한 예측과 기준 SQL의 행 튜플 집합을 비교하며, 미제출과 실행 실패를 분모에 포함합니다. 최종 응답 형식은 SQL 블록 하나로 고정했습니다. [표본과 DB 지문](results/post-sql-answer-check-314-sqlite100-12-v1/manifest.json) · [기준 SQL 검사](results/post-sql-answer-check-314-sqlite100-12-v1/gold_check.json)

Python 3.13.14, SQLite 3.53.1, LiteLLM 1.109.1을 사용했습니다. OpenAI SDK는 GPT‑4.1 계열에서 3.51.0, GPT‑6 Luna에서 3.57.0을 사용했습니다. 도구 내부 호출을 포함해 문항당 모델 호출 12회, 호출당 출력 4,096토큰으로 제한했습니다. 호출·문항·SQL 제한은 각각 120초, 480초, 30초이며 채점에서는 최대 100,000행을 읽었습니다. 모델 3종은 병렬로 실행했고, 각 모델은 B의 두 군 다음 D의 두 군을 실행했습니다. 조합당 동시성은 4입니다.

표의 합산은 같은 100문항을 모델·조건별로 반복한 600쌍의 기술 통계입니다. 조합당 한 번 실행했고, 각 모델에서 B와 D의 군 순서를 반대로 배치했습니다. GPT‑6 Luna는 별칭으로 요청했고, 실제 응답 모델 ID와 공급자가 반환한 fingerprint는 조합별 요약에 기록했습니다. [실행 시각과 산출물 SHA-256](results/post-sql-answer-check-314-sqlite100-12-v1/provenance.json)

## 재현

12회 고정 벤치 커밋과 위 제품 커밋 두 개를 체크아웃한 뒤 사용법의 `prepare`, `check-gold`, `matrix_ab.sh`, `compare`를 실행합니다. [벤치마크 사용법](https://github.com/jhpark324/Lang2SQL/blob/bf8bffa17f19cb0752b98f2e93c053e1679c76f5/bench/bird/README.md)

게시된 두 군의 채점 파일로 집계만 재현하려면 벤치마크 워크트리에서 `RESULTS`를 이 결과 디렉터리의 절대 경로로, `REPLAY_OUTPUT`을 새 출력 경로로 지정합니다.

```bash
"$BIRD_GPT41_PY" -m bench.bird.evaluate compare \
  --baseline "$RESULTS/baseline" --candidate "$RESULTS/candidate" \
  --output "$REPLAY_OUTPUT"
```
